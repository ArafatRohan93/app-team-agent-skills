# Config & flavors

**Files:** `lib/core/config/{flavor.dart,app_config.dart}`, `lib/main_{development,staging,production}.dart`, `lib/bootstrap.dart`

## Declaration
- `enum Flavor { development, staging, production }`
- `AppConfig` is an immutable value class: `flavor`, `appName`, `baseUrl` and timeouts, plus derived getters such as `isProduction`.
- Each `main_<flavor>.dart` does exactly one thing:
  ```dart
  void main() => bootstrap(
    const AppConfig(flavor: Flavor.staging, appName: '[STG] Acme', baseUrl: 'https://api.staging.acme.com'),
  );
  ```
- `bootstrap(config)` is shared by every flavor. It runs `runZonedGuarded`, `setupDependencies(config)`, `CrashReporter.initialize()`, sets `FlutterError.onError` and `PlatformDispatcher.onError`, sets `Bloc.observer`, then calls `runApp(App(config: config))`.

## Native side (generated by `scripts/bootstrap_app.py`)
| | development | staging | production |
|---|---|---|---|
| Android `applicationIdSuffix` | `.dev` | `.stg` | — |
| iOS bundle id | `<base>.dev` | `<base>.stg` | `<base>` |
| Launcher name | `[DEV] App` | `[STG] App` | `App` |

- **Android:** `productFlavors` in `android/app/build.gradle(.kts)` with `resValue("string", "app_name", …)`. The manifest label is `@string/app_name`.
- **iOS:**
  - Build configurations `Debug-<flavor>`, `Release-<flavor>` and `Profile-<flavor>`, each backed by `ios/Flutter/<Config>-<flavor>.xcconfig`, which includes the Pods xcconfig and `Generated.xcconfig`.
  - One shared scheme per flavor.
  - The `Podfile` maps every configuration.
  - `CFBundleDisplayName = $(FLAVOR_APP_NAME)`.

Run with `flutter run --flavor <f> -t lib/main_<f>.dart`. VS Code users get `.vscode/launch.json`.

## Usage
- Anything can read config through DI: `sl<AppConfig>()`, but inject it into constructors rather than calling `sl` inside classes.
- Branch on `config.flavor` or `config.isProduction`, never on `kReleaseMode`, when the question is "which environment?". `kReleaseMode` answers "is this an optimized build?", which is a different question.

## Secrets
Never put secrets in `AppConfig` literals. Pass them at build time and read them in the flavor entry point:
```dart
// flutter run --flavor production -t lib/main_production.dart --dart-define-from-file=secrets/production.json
const sentryDsn = String.fromEnvironment('SENTRY_DSN');
```
Add `secrets/` to `.gitignore` and keep a `secrets/example.json` in the repo.

## Adding a fourth flavor
Edit `FLAVORS` in `scripts/bootstrap_app.py` and re-run it on the project. It skips the Android block once `productFlavors` exists, so add the Android flavor by hand. Then add `lib/main_<flavor>.dart`, a launch config and a README row.

## Don'ts
- No per-flavor `if` statements scattered through features. Put the difference in `AppConfig` instead.
- Don't read `String.fromEnvironment` outside `main_*.dart`.
