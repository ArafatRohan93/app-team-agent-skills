# Localization

**Files:**
- `l10n.yaml`: arb-dir `lib/l10n/arb`, output `lib/l10n/gen`, `nullable-getter: false`.
- `lib/l10n/arb/app_en.arb`: the template.
- `lib/l10n/l10n.dart`: `context.l10n`. It also re-exports `AppLocalizations`.
- `lib/l10n/failure_l10n.dart`: `Failure.localizedMessage(l10n)`.
- `pubspec.yaml` has `flutter: generate: true`.

Generated code lives in `lib/l10n/gen/`. It's excluded from analysis and coverage, and regenerated by `flutter gen-l10n`, which also runs during `flutter run` and `flutter build`, and in `scripts/local_ci.sh`.

## Usage
```dart
import 'package:app/l10n/l10n.dart';

Text(context.l10n.homeWelcome(config.appName))
FilledButton(onPressed: retry, child: Text(context.l10n.commonRetry))
```

## Adding a string
Add the key and its `@key` metadata to `app_en.arb`, using placeholders for dynamic parts:
```json
"ordersCount": "{count, plural, =0{No orders} =1{1 order} other{{count} orders}}",
"@ordersCount": { "description": "Order list header", "placeholders": { "count": { "type": "int" } } }
```
Keys are named `<feature><Thing>` (`ordersEmptyTitle`) or `common<Thing>` for shared labels.

## Errors
Cubits don't build user-facing strings. States carry the `Failure`, and the widget localizes it:
```dart
OrdersError(:final failure) => ErrorView(message: failure.localizedMessage(context.l10n))
```
Extend `FailureL10n` when you add `Failure` subtypes. The sealed switch makes the compiler insist.

## Adding a language
Create `lib/l10n/arb/app_<locale>.arb` with the same keys and add the locale to `CFBundleLocalizations` in `ios/Runner/Info.plist`. `AppLocalizations.supportedLocales` updates automatically.

## Testing
`tester.pumpApp(...)` wires the localization delegates. For pure Dart tests, instantiate `AppLocalizationsEn()` directly (see `test/l10n/failure_l10n_test.dart`).

## Don'ts
- No hard-coded user-visible strings in widgets or cubits.
- Don't edit files in `lib/l10n/gen/`.
